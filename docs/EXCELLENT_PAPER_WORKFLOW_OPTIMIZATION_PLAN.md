# 优秀论文驱动的数学建模工作流优化计划

> 实施状态（2026-07-16）：P0 已落地到通用核心和矿井回归项目，包括逐问故事板、结果卡、摘要矩阵、插件验证梯度、强结论证据门禁和私有参考资料隔离。P1/P2 仍未实施。

## 1. 依据与边界

本计划基于本地私有优秀论文语料的结构审计与代表样本深读：

- 收到 PDF 57 篇，覆盖 2021--2025 年 A--E 题；
- 56 篇可进行文本结构分析，共 2731 页；
- 1 篇源 PDF 截断，标记为 `CORRUPT_SOURCE`，不推断其内容；
- 深读样本包括 2025 年 D 题两篇，以及 A、B、C、E 各一篇；
- 视觉抽查覆盖摘要首页、公式页、算法流程图页和结果分析页。

这些论文只用于提炼结构、论证和复核方法，不作为当前项目的数据、结果、参考文献或官方规则来源。不得复制原文、图表、模型结果和个性化表达，不得将私有语料纳入匿名支撑材料或普通 Git。

## 2. 从样本中得到的高价值模式

### 2.1 摘要是逐问结果清单，而不是背景介绍

代表论文通常在摘要中依次交代：小问目标、主模型或算法、关键结果、验证方法。关键方法和数字有明确视觉强调，背景只占很少篇幅。

应吸收：逐问覆盖、结果密度和验证闭环。

不应照搬：未经证据登记直接写入数字，或用“科学、稳定、最优”等词替代验证。

### 2.2 每个小问形成独立的论证闭环

常见有效结构为：问题分析、模型建立、模型求解、结果分析或检验、小结。高质量样本会解释为什么选择该模型，并用另一模型、物理规律、统计检验、扰动实验或人工判读进行交叉核验。

应吸收：每个小问有自己的输入、模型、求解、验证、结论和局限。

不应照搬：为显得复杂而堆叠模型名称，或只展示算法流程却没有前提、误差和失败条件。

### 2.3 验证方式随题型变化

样本中的有效验证包括：守恒规律、物理公式交叉核验、独立数值方法、统计显著性、替代模型、蒙特卡洛、扰动灵敏度和人工视频判读。不存在适用于所有题目的统一验证套餐。

工作流应由题目画像、假设风险和插件能力生成验证候选，再由 H4 人工选择；不能默认对全部题运行交叉验证、空间收敛或网络算法前提检查。

### 2.4 图表和公式承担论证任务

代表论文的流程图用于解释算法状态转移，公式页紧跟变量定义，结果图表与小问结论相邻。首页和正文整体信息密度高，但仍有清楚的章节层级和页码。

工作流应在出图前登记图表目的、支持的 claim、来源数据、比较尺度和论文位置，而不是生成后只检查文件存在。

### 2.5 优秀论文也不是不可质疑的标准答案

抽查中仍可见以下风险：题面条件被重复列为作者假设；“最优、稳定、合理”表述缺少足够证据；摘要结果与正文验证层级不完全匹配；模型较多但淘汰理由不清楚。

因此语料只能用于形成评审问题和质量基线，不能作为模型正确性的依据。

## 3. 优化目标

将现有“可复现、可审计、有人工作门禁”的工作流进一步升级为：

1. 每个小问在建模前形成可审查的论证路线；
2. 每个模型选择都有理由、替代方案和淘汰记录；
3. 每个关键结果都有题型适配的验证；
4. 摘要中的每个数字和强结论都能追溯到冻结证据；
5. 图表、公式、正文和代码使用一致符号与单位；
6. 最终论文不仅“检查通过”，而且能经受反方复审。

## 4. 拟新增的质量工件

### 4.1 `question_storyboard.yml`

每个小问一份，至少登记：

```text
question_id
decision_or_scientific_goal
inputs
required_outputs
core_difficulty
candidate_models
selected_model
selection_rationale
key_assumptions
algorithm_prerequisites
solver_plan
validation_plan
expected_figures_tables
claim_boundaries
paper_outline
reviewer
status
```

作用：在写代码前回答“为什么这样建模、如何证明结果可信、论文怎么讲”。

### 4.2 `question_result_cards.csv`

每个小问求解后登记：

```text
question_id
source_run_id
model_id
primary_metric
value
unit
uncertainty_or_tolerance
direct_evidence_id
validation_evidence_ids
decision_changed_under_alternatives
conditions
limitations
reviewer
status
```

作用：形成“建立—求解—检验—小结”的统一数据源，供摘要、结论和表格引用。

### 4.3 `abstract_matrix.csv`

每个小问一行：

```text
question_id
objective_sentence
method_sentence
result_sentence
validation_sentence
limitations_sentence
claim_ids
source_run_id
reviewer
status
```

自动检查只负责验证 claim、run、artifact 和 hash；最终文字由人工压缩。任何摘要数字必须来自冻结证据。

### 4.4 `model_rationale_cards/<model_id>.yml`

补充模型卡中容易被忽略的叙事字段：适用原因、未选模型、淘汰原因、理论前提、计算成本、解释性、预期失败模式和结论影响。

### 4.5 `figure_storyboard.csv`

在生成图片前登记：图表要回答的问题、支持的 claim、来源 artifact、横纵轴和单位、比较尺度、预期论文位置、最终是否保留。生成后再转入现有 `figure_manifest.csv`。

### 4.6 `paper_review_findings.csv`

记录反方复审问题：

```text
finding_id
review_axis
severity
paper_location
claim_id
finding
required_action
owner
reviewer
status
resolution_evidence
```

final 下所有 ERROR 必须关闭；WARNING 必须解决或明确保留限制。

## 5. 题型适配的验证梯度

通用核心只定义验证类别，具体方法由插件提供：

| 题型 | 最低验证要求 |
| --- | --- |
| 机制/物理 | 单位与量纲、守恒或基本不变量、边界/极限情形、独立物理关系交叉核验 |
| 网络/路径 | 图合同、路径可行性、动态边权前提、后备算法、替代结构比较 |
| 统计回归/分类 | 数据泄漏检查、时间或分层切分、基线模型、置信区间/校准、残差或错误分层 |
| 时间序列 | 严格时间切分、滚动回测、朴素基线、预测区间、概念漂移提示 |
| 评价排序 | 指标方向与单位、权重来源、替代权重、排名稳定区间、相关指标冗余检查 |
| 优化 | 可行性、目标与约束核验、多初值/多随机种子、最优性界或 gap、独立求解器交叉核验 |
| 启发式/仿真 | 随机种子、重复实验、置信区间、收敛趋势、计算预算和失败场景 |

H4 必须说明为什么选择这些验证，也要说明未选择其他验证的理由。

## 6. 写作质量门禁升级

### H1：题目叙事

- 每个小问有明确动作词、交付物和决策对象；
- 题面条件与作者假设分开；
- 识别最可能影响最终决策的风险。

### H3：模型选择

- 每个 main 模型至少有一个候选或被淘汰模型；
- 不能只以“常用、先进、效果好”作为选择理由；
- 算法前提、数据需求和失败模式已登记。

### H4：验证设计

- 每个高风险假设至少有验证、边界限定或经人工接受的限制；
- 计算预算根据决策风险和截止时间确定；
- 验证不通过时有明确 fallback。

### H6：结论边界

- 替代模型是否改变主要决策已检查；
- 样本集合、单位、时间窗口和指标定义可比较；
- “最优、稳定、鲁棒、准确”表述达到对应证据门槛。

### H7：论文叙事与图表

- 每个小问都有结果卡与段末小结；
- 摘要矩阵逐问完整，所有数字可追溯；
- 图表先有 storyboard，再有 manifest；
- 符号、单位、公式、代码变量和图表标签一致；
- 页数预算依据已确认官方规则，不以优秀论文页数均值替代规则。

### H8：双人反方复审

- 数值复核人尝试推翻关键结果；
- 论文合规复核人检查匿名、引用、占位符、未定义引用和文件合同；
- 两人必须不同，且所有审批对象 hash 固定。

## 7. 自动检查新增项

1. 摘要数字是否关联冻结 claim/evidence；
2. 强结论关键词与 `claim_kind`、证据类型是否匹配；
3. 每个小问是否有 result card 和正文位置；
4. main 模型是否有选择理由、前提和淘汰模型；
5. 题面条件是否被误标为作者假设；
6. 图表是否有 storyboard、claim、来源和人工复核；
7. 公式符号是否在符号表出现，单位是否一致；
8. 参考文献是否真实存在且正文引用；
9. 草稿与本地参考语料是否出现异常长的连续文本重合，仅提示人工检查，不自动判定抄袭；
10. 参考语料、提取文本和视觉渲染是否被匿名包 allowlist 排除。

## 8. 实施优先级

### P0：下一轮立即实施

1. `question_storyboard.yml` schema、模板和 H1/H3 检查；
2. `question_result_cards.csv` 与现有 artifact/evidence 联动；
3. `abstract_matrix.csv` 与摘要数字追溯检查；
4. 插件验证梯度及 H4 最低要求；
5. final 强结论证据规则扩展；
6. 参考语料永不进入 Git/支撑材料的回归测试。

### P1：P0 跑通矿井案例后

1. `figure_storyboard.csv` 与图表 narrative 检查；
2. `paper_review_findings.csv` 和 H7/H8 关闭规则；
3. 符号、单位、公式到代码的映射检查；
4. 页数预算、章节结果密度和摘要一页检查；
5. 为时间序列第二案例验证通用性。

### P2：两个不同题型稳定后

1. 本地参考语料 catalog、提取置信度和人工标注工具；
2. 写作结构对比报告和长文本重合提醒；
3. 评价优化、整数规划案例；
4. MATLAB、Word 模板与规定环境验证。

## 9. 验收标准

- 每个小问都有 storyboard、result card、验证证据和正文位置；
- 摘要中的每个数值可追溯到 frozen run，hash 匹配；
- main 模型有选择理由和淘汰模型，不存在模型名称堆叠；
- 题面条件不再作为作者假设重复登记；
- 每个题型达到插件规定的最低验证梯度；
- “最优、稳定、鲁棒、准确” major claim 同时具备 direct 与 validation/robustness evidence；
- 每张正文图先有 storyboard，后有 manifest，并经人工复核；
- H8 反方复审问题全部关闭或在结论中明确限制；
- 私有优秀论文、提取文本、作者学校信息和渲染图不进入 Git 或匿名提交包；
- 矿井 legacy 流程、generic 流程、LaTeX 和提交检查无回归。

## 10. 决策建议

优先实施 P0，而不是继续增加更多通用插件。当前工作流的主要增益点已从“能否运行”转向“能否把模型选择、验证和论文表达连成一条可复核的故事线”。P0 完成并在矿井案例上通过后，再用一个真实时间序列案例检验其通用性。
