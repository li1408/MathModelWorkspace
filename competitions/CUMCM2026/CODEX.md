# Codex 工作规则

## 项目定位

本目录是 2026 CUMCM 中文国赛正式工作区。Codex 的职责是辅助生成、修改、检查和修复项目内容，但不能替代队伍进行核心建模判断、结果解释和最终提交决策。

## 强制规则

- 每次修改前说明将要修改或创建哪些文件。
- 每次修改后总结改动、验证结果和下一步建议。
- 不编造数据、实验结果、参考文献、官方规则或提交要求。
- 不自动修改 `02_raw_data/` 中的原始数据。
- 不把比赛材料上传到公开平台。
- 不创建公开 GitHub 仓库，不启用 GitHub Pages。
- 不将 CUMCM 和 MCM/ICM 的论文格式、摘要要求或提交规则混用。
- 不在论文中引用不存在的图表或结果文件。
- 不把自动检查结果描述为“已完全满足官方规则”。
- 不为消除检查警告而编造假设验证、替代模型结果、论文结论、证据链接或图表复核状态。
- FIFO 检查只能表述为数值检验，不得表述为数学证明。

## 文件与数据规则

- 队友临时投递的题目、附件和说明文件先放入 `00_inbox/`。
- 整理 `00_inbox/` 时，先识别文件类型，再移动到 `00_official/`、`01_problem/` 或 `02_raw_data/`。
- 原始数据只读保存到 `02_raw_data/`。
- 大体积数据必须登记到 `02_raw_data/data_manifest.csv`。
- 每份原始数据应记录 SHA256 到 `02_raw_data/checksums.sha256`。
- 处理后数据必须由代码生成。
- 最终提交文件只允许复制到 `11_final_submission/` 后纳入 Git。
- 所有生成文件使用 UTF-8 编码。
- 显式 profile 运行必须使用唯一 `run_id`，并将结果写入 `05_model_results/runs/<run_id>/`；基线、替代模型和收敛实验不得互相覆盖。
- 论文结论和图表必须登记 `source_run_id`；证据文件必须记录 SHA256。
- 大型输入、缓存、临时目录和冷启动副本不得写入 C 盘。正式输入根只能通过 `CUMCM_INPUT_ROOT` 提供，不得写入个人绝对路径配置。
- `final` 模式下，未解决的高风险假设、无已验证证据的重要结论、未人工复核的正文图、冷启动失败或支撑材料绝对路径都必须阻断提交。

## AI 使用日志规则

每次实质性使用 AI 都要记录一条日志：

- `record_id`
- 日期时间
- 工具名称和版本
- 使用目的
- 是否采用
- 人工修改内容
- 人工验证方式
- 关联文件或论文章节

完整提示词保存到 `09_ai_logs/prompts/`，完整回复保存到 `09_ai_logs/responses/`，通过同一个 `record_id` 关联。

## 修改优先级

1. 符合 CUMCM 官方规范；不确定规则标注“需要根据当年官方文件确认”。
2. 保证模型、数据和论文可复现。
3. 适合三人团队协作。
4. 减少比赛期间重复劳动。
5. 允许后续扩展，但不牺牲当前流程简洁性。
